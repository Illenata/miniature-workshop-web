# Miniature Workshop — веб-компаньйон

Сайт показує мініатюри, пофарбовані в грі Miniature Workshop. Гравець ділиться ними одним посиланням, а глядач
переходить до сторінки гри в Steam і в Discord. ТЗ: `WEB_COMPANION_SPEC.md` у проєкті Anton-а.

**Стан:** фаза 1. Уже є база й міграції, `/healthz`, `GET /api/v1/gallery`, віддача файлів, сід на 1000 мініатюр і
сторінка `/gallery` з перемикачем «Картка / 3D», сторінки мініатюри `/m/<id>` і колекції `/c/<id>`, скарги, лендинг `/`, сторінки `/privacy` і `/terms`, адмін-панель.
Завантаження з гри ще немає.

## Структура

| Шлях | Що це |
| --- | --- |
| `apps/web` | Сторінки: React Router 7 із серверним рендером, Tailwind, рядки інтерфейсу в `app/i18n/*.json` |
| `apps/api` | Сервер на Fastify: API, віддача файлів, міграції (`drizzle/`), сід (`scripts/seed.ts`) |
| `packages/contract` | Zod-схеми контракту (розділи 5, 8 і 14 ТЗ): manifest, елемент мініатюри, коди помилок |
| `e2e` | Перевірки в браузері (Playwright), запускаються вручну проти локального сайту: `e2e/README.md` |
| `docker-compose.yml` | PostgreSQL, RustFS (локальне S3-сховище), API і сторінки |
| `.env.example` | Усі змінні з поясненнями |

Стек: Node 24, TypeScript, React 19, React Router 7, Tailwind 4, Fastify, Drizzle ORM, PostgreSQL 17, будь-яке S3-сумісне сховище, sharp, Zod.
Монорепо на npm workspaces і Turborepo.

## Запуск локально

Потрібні Docker Desktop, а для розробки й сіду ще Node 24 (підійде 22.18+).

```bash
# 1. Підняти все: базу, сховище й API. Перший раз збирає образ кілька хвилин.
docker compose up -d --build

# 2. Перевірити: має повернути {"status":"ok","db":"ok","storage":"ok"}
curl http://localhost:3000/healthz

# 3. Наповнити тестовими даними: 1000 мініатюр-плейсхолдерів
npm install
npm run seed

# 4. Подивитися: галерея на http://localhost:5173/gallery, API напряму:
curl "http://localhost:3000/api/v1/gallery?faction=gilded"
```

Після змін у коді образи треба перезібрати: `docker compose up -d --build`.

`.env` створювати не обов'язково: compose і скрипти беруть значення з `.env.example`, а `.env` лише перекриває
їх. Консоль сховища (RustFS) відкривається на http://localhost:9001 з логіном і паролем із `S3_ACCESS_KEY_ID` і
`S3_SECRET_ACCESS_KEY`. MinIO у 2025 році перестав публікувати образи, тому локально стоїть RustFS; на проді
підійде будь-який S3-сумісний сервіс.

### Розробка

```bash
docker compose up -d postgres storage # лише сервіси (api і web з compose при цьому не запускай)
npm install
npm run dev                           # API на :3000 і сторінки на :5173 з автоперезапуском
npm test                              # юніт-тести
npm run typecheck
```

Сід можна перезапускати з параметрами:

```bash
npm run seed -- --count 200     # інша кількість
npm run seed -- --reset         # спершу стерти всі мініатюри, колекції та їхні файли
npm run seed -- --reset --count 100 --glb D:\samples\miniature.glb   # справжня модель замість плейсхолдера
```

`--glb` кладе вказаний файл кожній мініатюрі окремою копією, тож з моделлю на 1,4 МБ і `--count 1000` у сховищі
опиниться 1,4 ГБ. Для перевірки 3D вистачить 100. Зразки моделей від команди гри в репозиторій не комітимо.

Щоб змінити схему бази, правиш `apps/api/src/db/schema.ts` і запускаєш `npm run db:generate`. У
`apps/api/drizzle/` з'явиться новий SQL-файл міграції, його треба закомітити. Сервер застосовує міграції сам при
старті.

## API (поточне)

| Маршрут | Що повертає |
| --- | --- |
| `GET /healthz` | 200, якщо база й сховище відповідають; інакше 503 |
| `GET /api/v1/gallery?cursor=&faction=painted\|gilded&sort=` | `{ items, next_cursor }`, 24 на сторінку |
| `GET /api/v1/miniatures/<id>` | Одна мініатюра; 404 для неіснуючої, схованої чи видаленої |
| `GET /api/v1/collections/<id>?cursor=` | `{ items, next_cursor, collection }`: мініатюри колекції, новіші першими; 404 для неіснуючої чи забаненої |
| `POST /api/v1/reports` | Скарга `{ miniature_id, reason, text }`: 201; 429 з `retry_after` понад ліміт |
| `GET /files/collections/<cid>/<mid>/<sha256>.<glb\|png\|webp>` | Файл мініатюри; для схованих і забанених — 404 |

`sort`: `newest` (за замовчуванням), `oldest`, `title_asc`, `title_desc`. Назви сортуються за українським
алфавітом (Ґ після Г, Є після Е, І та Ї після И), латиниця перед кирилицею, без урахування регістру: це колація
`mw_title` з міграції `0001`.

Пагінація курсорна, по `(ключ сортування, id)`. Курсор прив'язаний до фільтра й сортування: курсор з
`faction=painted` разом з іншим фільтром дає 400 `invalid_request`.

**Файли** у продакшні віддаються з окремого origin `files.<домен>`, локально з `http://localhost:3000/files`.
Шляхи містять хеш умісту, тому відповідь має `Cache-Control: immutable`. Віддаються лише три типи (glb, png, webp)
з `nosniff`, а журнал мазків не віддається ніколи. Якщо мініатюру сховали, її файли перестають віддаватися
протягом 30 секунд.

## Сторінки

### Лендинг `/`

Назва гри (замість логотипа, поки його немає), два речення про гру, кнопки «Wishlist on Steam» і «Discord» та
12 останніх мініатюр із посиланням на галерею. Кнопки Steam і Discord з'являються, коли задано `STEAM_STORE_URL` і
`DISCORD_URL`; поки посилання на Steam немає, головною кнопкою є «Відкрити галерею». Мініатюри беруться з першої
сторінки `GET /api/v1/gallery`. На ширині з п'ятьма колонками показано десять плиток, щоб ряди були повні. Якщо API
не відповідає, сторінка показує текст і кнопки без мініатюр.

### `/privacy` і `/terms`

Тексти лежать у Markdown: `apps/web/content/privacy.en.md`, `privacy.uk.md`, `terms.en.md`, `terms.uk.md`. Щоб
змінити текст, заміни файл і перезбери web (`docker compose up -d --build`): файли вбудовуються в збірку. Перший
заголовок `#` стає назвою вкладки. Markdown рендерить бібліотека `marked` на сервері. Обидві мовні версії мають
мати однакову структуру заголовків і списків, це перевіряє тест. Зараз у файлах чернетки з позначкою «Чернетка»
у першому рядку; остаточні тексти дає Anton.

Посилання на обидві сторінки стоять у підвалі всіх публічних сторінок.

### Галерея `/gallery`

`/gallery` рендериться на сервері й адаптована під телефон: 2 колонки від 360 px, до 6 на широкому екрані.
Фільтр за фракцією живе в URL (`?faction=gilded`). «Показати ще» дозавантажує сторінки без перезавантаження, а
кнопка «назад» зі сторінки мініатюри повертає на те саме місце з усіма дозавантаженими плитками. Без JS
«Показати ще» працює як звичайне посилання на наступну сторінку.

Сортування (нові, старі, назва А–Я, Я–А) теж живе в URL (`?sort=title_asc`) і поєднується з фільтром.

Перемикач «Картка / 3D» замінює прев'ю на `<model-viewer>` з автообертанням. Бібліотека (~290 КБ gzip)
віддається з нашого origin і завантажується лише при першому вмиканні 3D. Моделі отримують лише плитки в
області видимості, згори вниз, і качаються не більше двох одночасно. Скільки моделей може бути завантажено
разом, залежить від пристрою: 4 при економії трафіку чи 2G/3G, 6 на телефоні, 12–24 на десктопі
(`app/lib/model-slots.ts`). Плитка, що відійшла від екрана більш ніж на пів екрана, вивантажує модель. Вибір
режиму запам'ятовується в localStorage, а при `prefers-reduced-motion` моделі не обертаються.

Мова визначається за cookie `lang`, потім за мовою браузера. Перемикач у шапці — звичайна форма. Нові рядки
додаються в обидва файли `apps/web/app/i18n/en.json` і `uk.json`, тест перевіряє, що ключі збігаються.

У продакшні сторінки віддаються зі строгою CSP: скрипти лише свої або з nonce запиту, зображення лише зі свого
origin і origin файлів.

### Сторінка мініатюри `/m/<id>`

На телефоні в'ювер займає весь перший екран, на десктопі стоїть ліворуч від даних. Модель крутиться
перетягуванням, масштабується щипком чи коліщатком (з обмеженням, щоб камера не заходила всередину), кнопка AR
з'являється лише там, де AR підтримується. Вертикальний свайп по в'юверу прокручує сторінку.

Картка рендериться на сервері звичайним `<img>` і є першим, що бачить глядач. 3D-бібліотека починає
вантажитися при першій взаємодії зі сторінкою (скрол, дотик, клавіша) або через 3,5 с після завантаження
(`AUTO_START_MS` у `MiniatureViewer.tsx`). Так компіляція three.js (~0,5 с на середньому телефоні) не блокує
ні картку, ні перший дотик.

Open Graph і Twitter Card з OG-зображенням 1200×630; лічильник переглядів (+1 на завантаження сторінки людиною,
боти прев'ю не рахуються); `/m/<id>/qr.png` (QR 512×512), `/m/<id>/model.glb`, `/m/<id>/card.png`.
Кнопки Steam і Discord з'являються, коли задано `STEAM_STORE_URL` і `DISCORD_URL`. «Поскаржитися» поки
неактивна: скарги будуть разом з `POST /api/v1/reports`.

### Сторінка колекції `/c/<id>`

Заголовок «Майстерня <ім'я>», кількість мініатюр і дата першої публікації; той самий грід, що в галереї
(спільний компонент `TileGrid`), з перемикачем «Картка / 3D» і «Показати ще» по 24. Кнопка «Поділитися
колекцією» і QR-код, що розгортається на сторінці (`/c/<id>/qr.png`, 512×512). Прев'ю посилання бере
OG-зображення найновішої мініатюри. Забанена або неіснуюча колекція дає 404.

### Адмін-панель `/admin`

Вхід за паролем і кодом TOTP (Google Authenticator), сесія 12 годин. Увімкнення:

```bash
npm run admin:setup   # питає пароль, показує QR для застосунку і друкує два рядки для .env
```

`ADMIN_PASSWORD_HASH` (scrypt) і `ADMIN_TOTP_SECRET` вставляються в `.env`, після чого треба перезапустити API.
Поки хоч одне з них порожнє, адмінку вимкнено. П'ять невдалих спроб з однієї адреси блокують вхід на
15 хвилин (перезапуск API скидає лічильник); код TOTP діє один раз. Браузер тримає лише HttpOnly-cookie
`SameSite=Strict` з токеном сесії, у базі лежить тільки його хеш; POST з чужого origin відхиляється.
Маршрути `/internal/admin/*` на API викликає лише сервер сторінок: reverse proxy не має віддавати їх назовні.
Усі дії пишуться в журнал (`admin_actions`).

**Мініатюри** (`/admin/miniatures`): список від найновіших по 30, вкладки «Усі / Видимі / Сховані / Видалені» з
кількістю. «Сховати» прибирає мініатюру з галереї, її сторінка й файли починають віддавати 404 (файли протягом
30 секунд). «Показати» повертає її і закриває відкриті скарги на неї, інакше наступна скарга одразу сховала б
її знову. Прев'ю схованих мініатюр модератор бачить через `/admin/miniatures/<id>/thumb.webp`, що доступний
лише із сесією.

«Видалити» стирає всі файли мініатюри зі сховища назавжди й лишає в базі запис-надгробок зі статусом
`removed`; відкриті скарги на неї закриваються. Кнопка питає підтвердження, бо повернути файли неможливо. Якщо
сховище не відповіло, мініатюра лишається схованою, і кнопку можна натиснути ще раз.

**Скарги** (`/admin/reports`): черга мініатюр з відкритими скаргами по 30, першою йде та, на яку скаржилися
останньою. У рядку видно статус мініатюри, кількість скарг, причини й текст кожної скарги. Кнопки ті самі, що
в «Мініатюрах», плюс «Відхилити скарги»: вона закриває відкриті скарги, а мініатюру, яку скарги сховали
автоматично (`hidden_reason = reports`), повертає на сайт. Сховану модератором вона не показує. Мініатюра
зникає з черги, щойно на неї не лишається відкритих скарг («Відхилити скарги», «Показати» або «Видалити»).

**Стоп-слова** (`/admin/stop-words`): список, додавання (по одному в рядку, до 500 за раз), видалення і
перевірка довільного тексту. Кожне слово має прапорець зі ТЗ: «ціле слово» (за замовчуванням) або «підрядок».
Перед пошуком і текст, і слово нормалізуються однаково (`apps/api/src/lib/stop-words.ts`): нижній регістр, без
діакритики й невидимих символів, заміни 0→o, 1→i, 3→e, @→a, $→s, схожі кириличні літери замінюються латинськими
(а→a, о→o, х→x…), крапки, дефіси й пробіли всередині слова знімаються («f.u.c.k», «f u c k»). Фраза з кількох слів
шукається як ці слова підряд. Два записи, що після нормалізації однакові («Fück» і «fuck»), вважаються одним.
Перевірка показує, які слова знайшлися і як текст виглядає після нормалізації. Завантаження перевірятимуть title,
description і owner_name через той самий модуль (`StopWords.rejectedField`) і відповідатимуть 422 `text_rejected`.

**Статистика** (`/admin/stats`): за останні 30 днів (дні за UTC, сьогоднішній включно) завантаження, нові
колекції, перегляди сторінок мініатюр і скарги: підсумки й таблиця по днях. Завантаження рахується днем, коли
мініатюра з'явилася вперше (`created_at`), тож повторне «Поділитися» не додається, а видалена пізніше мініатюра
лишається в підсумку. Перегляди беруться з лічильника `daily_stats` (`miniature_views`). Відмови в завантаженні
показуються за кодами додатка B з лічильників `upload_rejected:<код>`; їх писатиме `POST /api/v1/uploads`
(`bumpDailyStat`), тож до появи завантажень ця таблиця порожня.

**Журнал** (`/admin/journal`): усі дії адмінки від найновіших по 50, фільтр «Усі / Модерація / Входи». На
головній адмінки лишаються десять останніх записів.

**Колекції** (`/admin/collections`): усі колекції й окремо забанені. «Забанити колекцію» (є і в рядку
мініатюри) прибирає із сайту колекцію з усіма мініатюрами та файлами, нічого не стираючи; «Розбанити» повертає
все. Завантаження із забаненої колекції відхилятиме `POST /api/v1/uploads` (403), коли він з'явиться.

### Скарги

Кнопка «Поскаржитися» веде на `/m/<id>/report`: причина (образливий вміст, спам, чужа робота, інше) і текст
до 300 символів, без реєстрації, працює й без JS. З однієї IP-адреси приймається одна відкрита скарга на
мініатюру (повторна мовчки не зберігається) і не більше `REPORTS_PER_IP_PER_DAY` (10) на добу. Скарги з
`AUTO_HIDE_REPORTS` (3) різних адрес ховають мініатюру до перевірки модератором (`hidden_reason = reports`).

IP-адреси зберігаються лише як HMAC-хеш із сіллю `IP_HASH_SALT`. Справжню адресу відвідувача API бере з
`X-Forwarded-For`, але лише від довірених сусідів (`TRUST_PROXY`: локальна й приватні мережі, тобто reverse proxy
і сервер сторінок).

Модератор отримує лист на `MODERATOR_EMAIL`: перша скарга надсилається одразу, наступні збираються й
надсилаються разом не частіше разу на годину. Локально листи ловить Mailpit: http://localhost:8025.
